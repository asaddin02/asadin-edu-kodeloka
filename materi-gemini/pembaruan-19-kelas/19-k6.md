## Modul Pembaruan 16: Pengujian Kinerja Hibrida (Beban API Protokol + Core Web Vitals di Peramban Nyata) dengan Modul `k6/browser`

- **Tingkat:** Lanjut
- **Ringkasan:** Menggabungkan ribuan Virtual Users (VU) di tingkat protokol HTTP (`k6/http`) untuk membebani backend sekaligus menjalankan beberapa instans Chromium sungguhan (`k6/browser`) untuk mengukur dampak beban server terhadap metrik LCP dan INP di sisi peramban.

### Penjelasan Mendalam & Praktik Terbaik Produksi (Standar 2025/2026)

Menggabungkan ribuan Virtual Users (VU) di tingkat protokol HTTP (`k6/http`) untuk membebani backend sekaligus menjalankan beberapa instans Chromium sungguhan (`k6/browser`) untuk mengukur dampak beban server terhadap metrik LCP dan INP di sisi peramban. Dalam lingkungan produksi modern, penerapan pola ini membantu mengurangi risiko keamanan, memudahkan pengamatan (*observability*), dan menyiapkan layanan menghadapi lonjakan beban kerja nyata.

```javascript
import { browser } from "k6/browser";
import { check } from "k6";

export const options = {
  scenarios: {
    ui_peramban: {
      executor: "shared-iterations",
      vus: 2,
      iterations: 5,
      options: { browser: { type: "chromium" } },
    },
  },
};

export default async function () {
  const page = await browser.newPage();
  try {
    await page.goto("https://kodeloka.asadinedu.com/");
    const judul = await page.locator("h1").textContent();
    check(judul, { "halaman utama termuat": (t) => t && t.length > 0 });
  } finally {
    await page.close();
  }
}
```

> **💡 Catatan Integrasi Kodeloka:** Modul ini dirancang untuk langsung ditambahkan ke akhir larik `K6_MOD_C` di `k6/app.js` (lalu jalankan `npm run extract`) sehingga memperluas cakupan kelas `k6` dari **15 modul** menjadi **18 modul** berstandar terbaru.


## Modul Pembaruan 17: Pemodelan Trafik Dunia Nyata (*Open vs Closed Workload Model*) dengan Executor `ramping-arrival-rate` dan `dropped_iterations`

- **Tingkat:** Lanjut
- **Ringkasan:** Memahami mengapa executor berbasis iterasi tertutup (`ramping-vus`) melambat mengikuti kelambatan server, sedangkan model terbuka **`ramping-arrival-rate`** terus mengirim laju permintaan per detik (RPS) yang konstan persis seperti perilaku pengunjung nyata saat *flash sale*.

### Penjelasan Mendalam & Praktik Terbaik Produksi (Standar 2025/2026)

Memahami mengapa executor berbasis iterasi tertutup (`ramping-vus`) melambat mengikuti kelambatan server, sedangkan model terbuka **`ramping-arrival-rate`** terus mengirim laju permintaan per detik (RPS) yang konstan persis seperti perilaku pengunjung nyata saat *flash sale*. Dalam lingkungan produksi modern, penerapan pola ini membantu mengurangi risiko keamanan, memudahkan pengamatan (*observability*), dan menyiapkan layanan menghadapi lonjakan beban kerja nyata.

```javascript
export const options = {
  scenarios: {
    flash_sale_rps: {
      executor: "ramping-arrival-rate",
      startRate: 10,
      timeUnit: "1s",
      preAllocatedVUs: 50,
      maxVUs: 300,
      stages: [
        { target: 200, duration: "2m" }, // Naik ke 200 permintaan/detik
        { target: 200, duration: "5m" }, // Tahan 200 RPS
        { target: 0, duration: "1m" },
      ],
    },
  },
};
```

### Penjelasan Mendalam & Praktik Terbaik Produksi (Standar 2025/2026)

Memuat ratusan ribu baris akun uji CSV/JSON hanya satu kali di memori bersama menggunakan `SharedArray` dari `k6/data` agar tidak menduplikasi memori di setiap VU, serta mengalirkan hasil uji langsung ke Prometheus/Grafana. Dalam lingkungan produksi modern, penerapan pola ini membantu mengurangi risiko keamanan, memudahkan pengamatan (*observability*), dan menyiapkan layanan menghadapi lonjakan beban kerja nyata.
